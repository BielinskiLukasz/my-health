# Quick Task 260917-g44: Fix Gap G-02-5 Summary

**Added `getYAxisDomain(metric)` utility using Recharts' `dataMin - N` / `dataMax + N` domain-formula syntax, wired into both YAxis branches of MetricChart.tsx so weight/heartRate/temperature charts scale to their period's data range instead of always starting at 0.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments
- Weight, heart rate, and temperature charts now render a Y-axis scaled to `dataMin`/`dataMax` (with fixed per-metric padding: +/-1kg, +/-5bpm, +/-0.3C) instead of always including 0
- Steps, sleep, and water charts are unaffected — `getYAxisDomain` returns `undefined` for them, which Recharts treats as a no-op, preserving the existing 0-start axis
- The same domain is applied to both the `LineChart` and `BarChart` `YAxis` elements, so the yearly view (which forces a bar chart for all metrics per D-06) also scales correctly for weight/heartRate/temperature
- G-02-5 marked `resolved` in `02-UAT.md` with root cause and fix-commit reference, following the G-02-1/G-02-2 pattern

## Files Created/Modified
- `src/utils/chartDomain.ts` - New `getYAxisDomain(metric)` utility; returns a padded dataMin/dataMax domain tuple for weight/heartRate/temperature, `undefined` for steps/sleep/water
- `src/utils/chartDomain.test.ts` - 4 assertions covering all three scaled metrics plus the unchanged pass-through metrics
- `src/components/Charts/MetricChart.tsx` - Imports `getYAxisDomain`, computes `yAxisDomain` once per render, passes `domain={yAxisDomain}` to both the `LineChart` and `BarChart` `YAxis` elements
- `.planning/phases/02-charts-visualization/02-UAT.md` - G-02-5 gap entry updated to `status: resolved` with `root_cause`, `resolved_by` (commit `6dc699a`), and `resolved_at: 2026-09-17`

## Decisions Made
- Used Recharts' native `'dataMin - N'` / `'dataMax + N'` domain string-formula syntax (confirmed supported in the installed recharts ^3.10 via `YAxis.d.ts`) rather than computing min/max manually in `MetricChart.tsx` — this keeps the padding relative to whichever period's filtered dataset (`useChartData`) is currently rendered, with zero extra JS computation.
- Fixed per-metric padding constants (not a percentage) per the plan spec: weight +/-1kg, heartRate +/-5bpm, temperature +/-0.3C.
