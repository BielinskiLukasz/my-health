<objective>
Narrow decision D-06 in `src/components/Charts/MetricChart.tsx` so the yearly (Y) period no longer forces every metric into a bar chart. Continuous metrics (weight, sleep, heartRate, temperature) should render as a line chart in Y — matching their existing W and M rendering — while discrete/count metrics (steps, water) keep rendering as a bar chart in every period, exactly as today.

Investigation confirmed there is no rendering-safety reason for the current blanket override: `02-CONTEXT.md`'s original D-06 rationale ("daily granularity is too noisy at yearly scale") is about aggregating daily data into 12 monthly points — a concern `aggregateMonthly()` already fully resolves before the chart ever sees the data — not about a Recharts LineChart limitation. The yearly data shape from `useChartData` is the same `{date, value}[]` contract used by W/M (just with `"YYYY-MM"` keys and up to 12 points), `aggregateMonthly()` in `src/utils/aggregation.ts` only ever emits an entry for a month with actual data (never a null/placeholder value), and `xTickFormatter`'s Y-period date parsing plus `Line`'s `connectNulls={false}` are both independent of chart type and already correct for this data shape. No prior RESEARCH.md or CONTEXT.md note ties bar-for-Y to a rendering bug — it was a purely stylistic blanket choice, not a technical constraint, so narrowing it to only the metrics that were always meant to be discrete (steps, water) is safe.

Purpose: Continuous health metrics (weight, sleep, heart rate, temperature) read more honestly as a trend line — bars visually imply discrete/independent daily totals, which misrepresents an averaged continuous measurement even when aggregated monthly. This restores visual consistency with the W/M views for those four metrics while preserving bar charts for the two metrics (steps, water) that really are counts.
Output: `MetricChart.tsx` chartType computation driven purely by `METRIC_CHART_TYPE[metric]`, with an updated D-06 comment reflecting the narrowed rule.
</objective>
