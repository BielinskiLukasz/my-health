<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → Dexie | Sleep time strings (HH:MM), step counts, water ml, bpm go from form inputs into IndexedDB |
| localStorage → UI state | Dark mode and height values read from localStorage on mount; user could manipulate localStorage directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | SleepForm time inputs | low | mitigate | input[type="time"] constrains to valid HH:MM format; overnight detection logic explicitly validates that wakeTime != beddingTime (zero-duration check per UI-SPEC.md E4 error state); differenceInMinutes validates both times parse successfully |
| T-02-02 | Tampering | localStorage dark mode value | low | accept | Dark mode affects only visual class on documentElement; no security impact; adversarial localStorage manipulation has no exploitable effect |
| T-02-03 | Tampering | HeartRate multi-entry edit | low | mitigate | Edit targets the most recent entry by timestamp; delete targets specific entry id; no entry is silently affected by operations on another entry (per D-16 multi-per-day cardinality) |
| T-02-04 | Denial of Service | Sleep duration edge case | low | mitigate | Wrap differenceInHours/differenceInMinutes in try/catch; on parse failure set duration null and show "--"; form remains submittable but shows invalid duration |
</threat_model>
