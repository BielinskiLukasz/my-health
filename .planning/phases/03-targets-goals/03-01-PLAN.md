<objective>
Build the target engine end-to-end for one axis of Phase 3: a user can set a deadlined target
(value + date) for weight, sleep, steps, water, or heart rate; the app persists it in Dexie,
projects pace via a 7-day linear trend, and shows a red/yellow/green/grey on-track status plus a
dashed reference line on the chart screen and a progress bar + badge on the Dashboard tile.
Temperature never gets target UI (not in TARG-01's metric list, and PB-eligible metrics exclude
it too per D-21). This is the phase's tracer: it proves the Dexie->calc->hook->chart-UI->
dashboard-UI path end to end for the "target" concept before Plan 03-02 (streaks/PBs) and
03-03 (exercise proxy) expand outward.

Purpose: without a working target+pace+color engine, nothing else in Phase 3 (streaks, PB
surfacing, exercise proxy status) has anything to attach to — this is the load-bearing layer.
Output: Dexie schema v3 (`targets` table), `targetCalcs.ts` (pace/trend/status pure functions,
TDD), `useTargetData` hook, `TargetModal` component, and extended `MetricChart`/`MetricTile`.
</objective>
