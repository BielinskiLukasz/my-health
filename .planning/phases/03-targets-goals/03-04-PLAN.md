<objective>
Close the two Critical gaps in Phase 3's verification report that share the same personal-best
and MetricChart call sites: CR-01 (a `0` fallback value falsely triggers and permanently poisons
personal-best detection for min-direction metrics) and CR-02 (`MetricChart` violates React's
Rules of Hooks by calling hooks after an early return, risking a crash on invalid metric
navigation). Also close the two directly-adjacent Warnings in the same code: WR-01 (the
personal-best Dexie write is an unobserved render-time side effect) and WR-02 (personal-best
records get stamped with today's date even when the triggering value isn't from today).

Purpose: These four defects, found by the Phase 3 code review and verification pass
(03-REVIEW.md, 03-VERIFICATION.md), directly block Success Criteria #2 and #4 — target/PB color
coding and personal-best flagging are both currently unreliable or actively corrupting data.
Output: A corrected `usePersonalBestData` hook contract (`isPersonalBest` derived from an
explicit, never-a-sentinel value), a new pure `resolveTodayValueForPbCheck` resolver, and a
`MetricChart` that calls every hook unconditionally on every render.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Weekly/period chart data (possibly empty) -> personal-best check | A missing-data case must never be represented as a real numeric value, or it corrupts a persistent cache. |
| React Router `:metric` URL param -> MetricChart hook call order | Attacker-controllable string in the URL, but self-inflicted in a single-user client app; the real risk is an accidental crash, not data exposure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Tampering | usePersonalBestData / db.personalBests | high | mitigate | `resolveTodayValueForPbCheck` returns `null` (never a numeric fallback) when no entry exists for the checked date, so `isNewPersonalBest` is never invoked with a sentinel like `0` — closes CR-01's permanent cache-poisoning bug (data-integrity threat: a malformed input could otherwise corrupt calculations for every future comparison against that record). |
| T-03-11 | Denial of Service (crash) | MetricChart.tsx render | high | mitigate | All hooks (`useChartData` x2, `useTargetData`, `usePersonalBestData`) are called unconditionally before any return; the invalid-metric branch is expressed only via a post-hook `useEffect` redirect plus a JSX-level `return null` — eliminates the "Rendered fewer hooks" crash (CR-02). |
| T-03-12 | Repudiation | personalBests date stamping | low | mitigate | Bump writes now only ever fire for a value whose own entry date is today, and persist that same date — WR-02 fix prevents mislabeling the PB audit trail with today's date for a past-dated value. |
| T-03-13 | Information Disclosure (unhandled rejection) | usePersonalBestData Dexie write | low | mitigate | The Dexie write is wrapped in `.catch` so a failed write can never surface as an unhandled promise rejection (WR-01 partial fix; the write is also moved off the render path into a useEffect). |
| T-03-14 | Tampering (XSS) | React JSX rendering of metric/target/PB values | low | accept | All values render as React text children (auto-escaped); no `dangerouslySetInnerHTML` exists in either touched file and none is introduced by this plan. |
